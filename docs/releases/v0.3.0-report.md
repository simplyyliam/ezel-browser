## MANUAL TESTS

One fresh `npm run tauri dev` (close every Ezel window first). Steps per feature; "expect" is what should happen.

### 0. Auto-updates
1. Close Ezel. In Git Bash: `EZEL_UPDATE_MOCK=1 npm run tauri dev`. After about 3 seconds, open or peek the sidebar: expect "Update ready · Restart to apply" above the footer buttons; hovering shows "Ezel 9.9.9 is downloaded…".
2. Click it: expect "Restarting…", then Ezel restarts (debug: it only restarts) with your tabs back.
3. Without `EZEL_UPDATE_MOCK`, a debug build shows no note and makes no update request.
4. The real path, after you've added the two secrets and published v0.3.0: install v0.3.0, release a v0.3.1 later; within 20 seconds of a launch (or a day) the note appears; clicking it closes Ezel, a small installer window runs, Ezel reopens on 0.3.1.

### 1. Folders
1. Right-click a temp tab › **New Folder with Tab**: expect a folder at the end of the pinned list holding the tab, its name a field reading "New Folder" (selected). Type "Refs", Enter.
2. Right-click empty sidebar space › **New Folder**, and the **+** menu › **New Folder**: each adds a folder in rename mode. Escape keeps "New Folder".
3. Drag a tab onto the **middle** of a folder's row: the row lights up; drop: the tab goes in (at the end). Drag onto the **top or bottom edge** of a closed folder's row: a line above/below the folder; drop: the tab lands beside it.
4. With a folder open, drag between its tabs: a line between them; drop reorders. Drag a tab out of the folder to the pinned list and to the temp list: it leaves the folder (into temp it becomes unpinned).
5. Right-click a folder row: Rename Folder…, New Tab in Folder, Collapse/Expand Folder, Unload Folder (only with a loaded tab), Move to Space ▸ (with 2+ spaces), Unpack Folder, Delete Folder…. Delete on a folder with tabs asks first ("Its 2 tabs will be closed too…"); Ctrl+Shift+T then brings a tab back. Delete on an empty folder doesn't ask.
6. Tab menu › **Move to Folder ▸** lists the space's other folders.

### 2. Sidebar context menus
1. Right-click: a swatch, a pinned tab, a temp tab, a folder, the space title, empty sidebar space. Each opens its menu, and **no menu or submenu goes past the sidebar's right edge** (try right-clicking near the right edge, and open Move to Space ▸ / Close Multiple Tabs ▸).
2. On a background (not shown) loaded tab: **Reload Tab** is there and reloads it (watch its spinner).
3. Space title › **Delete Space…** on a space with tabs: the alert offers Cancel / Close Tabs / Move to "<space>" (with 3+ spaces: a "Move them to" picker and "Move and Delete"). Move: its tabs and folders appear at the end of the other space and the page you were on stays. Close Tabs: they go; Ctrl+Shift+T brings them back. An empty space deletes without asking. With one space, Delete isn't offered.
4. Copy Link, Duplicate Tab, Pin/Unpin, Add to / Remove from Swatches, Move to Space work from tab and swatch menus.

### 3. Site identity + quick tabs
1. Open `https://example.com`. Hover the top edge: the middle shows a lock and **example.com** (with `www.` it's quiet, the domain bold).
2. Open `http://neverssl.com`: an open lock and "Not secure". Open `https://expired.badssl.com`: Ezel's certificate page (see 8) and the peek shows a red warning with "Certificate problem".
3. Click the domain: the bar grows with the site panel (connection, Permissions, All Site Permissions…, Clear This Site's Data…). It stays while the pointer leaves; Esc, a click elsewhere, or clicking the page closes it. **Clear This Site's Data…** asks in place; Clear Data reloads the page signed out, with a "Site data cleared" toast.
4. Quick tabs: in a folder tab, the left of the peek shows the folder's other tabs as icons; outside a folder, your Swatches. Clicking one switches.
5. Ctrl+L / Ctrl+K: the palette's top line holds the full address, selected.
6. On a site with "Sign in with Google" (e.g. a site using Google sign-in): the popup is a small window whose title starts with `accounts.google.com — …`; signing in completes and the popup closes itself.
7. Ctrl+D on a temp tab: "Pinned" toast and it moves to the pinned list; on a pinned tab: "Already pinned"; on a swatch: "Already in Swatches".

### 4. Website context menu
1. Right-click: a link (Open Link in New Tab, Copy Link, Inspect), an image (Open Image in New Tab, Copy Image, Copy Image Address, Save Image As…), selected text (Copy, Search for "…"), a text field (Undo/Redo, Cut, Copy, Paste, Select All), the page background (Back/Forward (only with history), Reload, Inspect). The menu draws at the pointer, over the page, in Ezel's style.
2. Open Link in New Tab: a new temp tab appears on top, not selected and dimmed (unloaded) until clicked. Search for "…": a new Google tab, selected. Paste into a field, Copy Image then paste in Paint, Inspect opens DevTools on that element.
3. Esc or clicking the page closes the menu without doing anything; right-clicking again opens a fresh one.

### 5. Find in page
1. Ctrl+F (from the page or the sidebar): a small bar in the page's top-right corner, focused. Type a word: matches highlight, "1 of N" shows; Enter / Shift+Enter move; no match: "No matches" in red.
2. Esc closes it, highlights go, and typing goes to the page again. Ctrl+F again reselects the text. Switching tabs closes it.

### 6. Downloads
1. Download a file (e.g. `https://speed.hetzner.de/100MB.bin` or any PDF): no Edge flyout; the footer's download button gets a dot; open the list: name, a bar and "x MB of y MB" (a spinner when the size is unknown); × cancels ("Cancelled").

### 7. HTML fullscreen
1. On YouTube, press the video's fullscreen button: the video fills the whole screen; no sidebar, titlebar or frame.
2. Esc returns everything as it was (maximized stays maximized). So does the video's own button. Ctrl+Tab while fullscreen leaves fullscreen.

### 8. Error and crash pages
1. Type `https://this-does-not-exist-ezel.test`: "Can't find this-does-not-exist-ezel.test" with Try Again and Change Address….
2. Turn Wi-Fi off, reload: "You're offline"; on, Try Again: the page returns.
3. `https://expired.badssl.com`: "This connection isn't private", Go Back (or Try Again), no way past.
4. Crash: in Task Manager › Details, end the shown tab's `msedgewebview2.exe` renderer (the one whose memory jumps when you scroll the page): "This page stopped working" with Reload; Reload brings it back.

### 9. Site permissions
1. Open `https://webcamtests.com` (or any camera test) and start the camera: the titlebar peek opens by itself with "**webcamtests.com** wants to use your camera", Don't Allow / Allow. Allow: the camera works.

### 10. Recently closed tray + link status

### 11. Import from Zen

## NEEDS YOUR DECISION

### Do this before `npm run release` (auto-updates)
1. **Add the updater key to GitHub Actions secrets.** I generated the key pair, but setting repository secrets was blocked by my permissions, so it's yours to do. From the repo root in Git Bash:
   ```
   gh secret set TAURI_SIGNING_PRIVATE_KEY --repo simplyyliam/ezel-browser < .private/updater/ezel-updater.key
   gh secret set TAURI_SIGNING_PRIVATE_KEY_PASSWORD --repo simplyyliam/ezel-browser < .private/updater/password.txt
   ```
   Without them the release workflow fails at the build step (it now signs update bundles).
2. **Save both in your password manager**: the private key file `.private/updater/ezel-updater.key` and its password `.private/updater/password.txt` (both git-ignored, never committed). If either is lost, installed copies of Ezel can never update again. Once saved, you can delete `password.txt`.
3. The public key is in `src-tauri/tauri.conf.json` (`plugins.updater.pubkey`); that one is meant to be public.

### Choices I made for you
- **Releases are no longer marked pre-release** (`prerelease: false` in the workflow): the updater reads GitHub's `releases/latest`, which skips pre-releases. They're still drafts until you publish them.
- **Update timing**: the first check 20 seconds after launch (the restored tab loads first), then every 24 hours, skipped while an update waits. Release builds only; never in `perf` builds.
- **Update bundles are signed only in CI** (`src-tauri/tauri.release.conf.json` turns on `createUpdaterArtifacts`), so a local `npx tauri build` still works without the private key.
- **Folders**: a new folder is called "New Folder" and opens as a name field; names are 1–60 characters, one line. "New Folder with Tab" on a temp tab or a swatch puts the folder at the end of the pinned list (the tab becomes pinned); on a tab already in a folder, the new folder goes right after that folder (folders don't nest). Folders themselves can't be dragged yet (Move to Space moves one). Dragging onto a closed folder doesn't spring it open.
- **Deleting**: a folder or space with tabs asks first; an empty one doesn't. Tabs closed that way go on the Ctrl+Shift+T stack. Deleting a space defaults to moving its tabs to the space shown next.
- **Tab menu groups**: four groups now (page / keep / place / close) instead of three, since folders added items.
- **Sidebar menus are bounded by the sidebar card**: they shift left to fit; a submenu flips left or drops below its item when there's no room beside it.
- **The page menu is drawn by Ezel's UI** (cut out of the page like every popup), not injected into the page: a page can't see or change it. Items that can't run (Paste with nothing to paste, Back without history) are hidden, not dimmed (HIG, and Ezel's menu rules). **Open Link in New Tab** opens a temp tab on top, not selected and not loaded until you open it (light: costs nothing until then); Chrome loads it in the background.
- **Find in page** uses WebView2's native find, which needs a runtime from 2025 or later; older ones get a "Find needs a newer WebView2" toast.
- **Downloads**: the list is for the session only (not saved); at most 50 entries. There's no toast when a download starts (the button's dot shows it), only when it finishes or fails. No pause/resume yet. Opening a file goes through Explorer, so Windows' "downloaded from the internet" warnings apply.
- **Error pages**: Ezel's page only for offline, not found, not answering, timed out, certificate and crashed renderer; anything else (SmartScreen, cancelled loads, sign-in prompts, unknown errors) stays WebView2's. There's **no way past a certificate error**, not even for local dev servers with self-signed certificates.
- **Permissions**: answers are remembered for good (Allow and Don't Allow alike), per origin; Esc on the prompt declines once. A tab that isn't on screen can't ask (declined once). Sign-in popups and other kinds (MIDI, sensors, window management…) keep WebView2's own prompt. Grants given to WebView2's prompt before v0.3.0 stay in its profile.
- **Sign-in popups** now open in Ezel's own window (titled with the domain); if that window can't be created, WebView2's own plain window is used, as before.
- **Site identity**: the registrable domain is a heuristic (last two labels, three for `co.uk`-style suffixes), not the Public Suffix List. Certificate details (issuer, expiry) aren't shown, only the status.
- **Fullscreen**: switching tabs leaves fullscreen.
- **Recently closed chips**: the last 5, shown only while nothing is typed (so not with Ctrl+L, whose field holds the address).
- **Zen import**: Essentials are imported only with the Essentials row checked (on by default); nested folders become their own folder named "Parent / Child"; split views and live folders become plain folders; empty and Glance tabs and non-web addresses are skipped; Zen's space icons map to Ezel's when the names match, else the default icon. Logins, passwords, cookies, history, containers and themes are **not imported**.
- **Polish item "Motion tokens" skipped** (too big for a polish item: every animated component).
- **Mid-run requests**: the HIG review and the import research (Chrome, Edge, Arc, Dia) were done as `fix/hig-review` and `docs/browser-import-research`; the actual Arc/Chrome/Edge importers stay in v0.6.0 as planned.

## PERFORMANCE

Release builds with the measurement hook (`npx tauri build --no-bundle --features perf`), v0.2.1 (built from its tag) and v0.3.0, measured in the same session with `scripts/measure-memory.ps1`, alternating versions, one run each per round. Private working set (Task Manager's number) / private bytes, whole process tree.

| Scenario | v0.2.1 | v0.3.0 | Change (WS / bytes) | Processes (renderers) |
|---|---|---|---|---|
| just launched | 327.7 / 438.2 MB | 290.8 / 414.4 MB | −11% / −5% | 9 (3) → 8 (2) |
| 1 tab | 169.5 / 278.9 MB | 195.0 / 282.5 MB | **+15%** / +1% | 8 (2) → 8 (2) |
| 5 tabs | 306.2 / 470.3 MB | 290.2 / 470.8 MB | −5% / 0% | 12 (6) → 12 (6) |
| 10 tabs, 1 visible | 873.1 / 1101.2 MB | 866.9 / 1060.6 MB | −1% / −4% | 12 (6) → 12 (6) |
| after 5 min idle | 696.8 / 809.5 MB | 452.6 / 687.9 MB | −35% / −15% | 8 (2) → 8 (2) |

- **Only round 1 is usable.** In round 2 both versions' windows were closed partway (exit code 0, a normal close, not a crash: likely while the machine was in use), so there's one sample per scenario and version. Day-to-day site variance is a few percent, and one sample is noisier than the usual median of runs.
- **1 tab: +15% private working set, flagged per the rules** (over 10%). Private bytes (committed memory) moved only +1% and the process count is the same, which points at noise in working-set trimming rather than new memory. v0.3.0 adds per-tab event handlers (menu, downloads, find, permissions, status text, errors), each a small COM object, not a renderer. Worth re-measuring with `-Runs 3` before deciding; I'd treat it as noise unless it repeats.
- Nothing new polls while idle. The only new timer is the updater's thread, which sleeps 24 hours between checks (release builds only, never in `perf` builds). No new feature keeps a hidden tab awake.
- Compared with docs/perf/results.md (2026-10-21): today's v0.2.1 numbers are higher than that day's for 1/5/10 tabs (sites and the WebView2 runtime vary day to day), so the same-session v0.2.1 → v0.3.0 comparison above is the one to go by.
