# Site identity (v0.3.0)

Why: a tab shows the title the page picks, so a phishing page titled "Google" looks like Google (security review, open risk 1). Checked 2026-10-23.

- **What browsers show.** Chrome and Edge show the host in the address bar and de-emphasise everything but the registrable domain while typing isn't active; Safari shows only the registrable domain by default. A lock (or "Not secure" for HTTP, a red warning for certificate errors) sits before it, and clicking it opens a site panel: connection, certificate, permissions, cookies and site data. Ezel has no address bar, so the host and lock live in the titlebar peek and the panel opens inside it.
- **Registrable domain.** The real rule is the Public Suffix List (~10k entries). Ezel uses a small heuristic (`shared/site.ts`): the last two labels, or three when the second-level label is a common public one (`co.uk`, `com.au`…). An unknown public suffix only makes one more label strong; it never hides the host.
- **Certificate errors.** WebView2 raises `ServerCertificateErrorDetected` (ICoreWebView2_14, 1.0.1245+) for every resource with an unverifiable certificate, before its own warning page. Ezel counts it for the page only when the request's host is the page's own (the navigation's target, recorded at `NavigationStarting`), and clears it on the next navigation. The default action (WebView2's warning page) stays.
- **Clearing a site's data.** WebView2's `ClearBrowsingData*` work on the whole profile only. The DevTools protocol's `Storage.clearDataForOrigin` with `storageTypes: "all"` clears cookies, local and session storage, IndexedDB, Cache Storage and service workers for one origin; Ezel builds the origin from the parsed tab URL and reloads after.
- **Sign-in popups.** Tauri's `NewWindowResponse::Create` hands WebView2 a window Ezel built in the same environment (`window_features`), so `window.opener` works; wry defers the new-window handler, so building the window there doesn't deadlock. wry's own `WindowCloseRequested` only destroys the webview's container, so Ezel closes the whole window itself.

Sources: Chromium "URL display guidelines" (chromium.googlesource.com/chromium/src/+/main/docs/security/url_display_guidelines/url_display_guidelines.md), https://publicsuffix.org, https://learn.microsoft.com/microsoft-edge/webview2/reference/win32/icorewebview2_14, https://chromedevtools.github.io/devtools-protocol/tot/Storage/#method-clearDataForOrigin, wry 0.57 `src/webview2/mod.rs` (NewWindowRequested, WindowCloseRequested).
